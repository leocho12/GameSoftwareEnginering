- **미정:** 추가 결정이 필요한 항목.

개발 협업 규칙과 현재 코드의 기술 과제는 [AGENTS.md](../AGENTS.md)를 따른다. 이 기획서의 기능 설명은 구현 완료를 의미하지 않는다. 변경된 사용자 결정은 두 문서의 관련 항목에 함께 반영한다.

## 3. 핵심 플레이 경험

### 3.1 계속 이어지는 탐험

플레이어가 기존 탐험 영역을 벗어나면 새로운 지역이 이어진다. 이전 장소로 돌아왔을 때 플레이어의 행동과 진행 상태가 남아 있어야 한다. 월드 확장은 지형뿐 아니라 임무와 발견 요소로 연결하는 것을 목표로 한다.

### 3.2 동료와 함께하는 지휘관의 삶

플레이어는 인간 지휘관이며 인형들과 함께 임무를 수행한다. 동료와의 관계가 지휘 결정과 이후 행동에 의미를 갖도록 하는 것을 설계 방향으로 제안한다. 신뢰 수치, 개별 동행 조건 등 구체적인 규칙은 미정이다.

### 3.3 원작과 나란히 진행되는 개인 이야기

원작의 주요 사건은 같은 흐름으로 진행되고 원작 지휘관도 존재한다. 플레이어는 별도 임무와 관계를 통해 자신의 이야기를 만든다. 원작 주요 사건의 결말과 플레이어가 바꿀 수 있는 지역 사건의 범위를 구분한다.

### 3.4 소속을 선택하는 모험

그리폰에 남아 활동할지, 인형들과 떠나 독자적으로 활동할지를 선택할 수 있다. 어느 진로에서도 탐험과 RPG 진행이 이어지는 방향으로 설계한다. 잔류를 실패, 독립을 유일한 정답으로 취급하지 않는 것은 잠정적인 서사 원칙이다.

## 4. 기본 플레이 흐름 — 잠정안

**거점에서 준비 → 임무 선택 → 지역 탐험 → 전투·대화·발견 → 결과와 보상 → 정비·성장·관계 변화 → 다음 탐험**

| 구간 | 플레이어의 활동 | 필요한 기능 |
|---|---|---|
| 준비 | 임무 확인, 동료·장비 준비 | 대화, 임무 목록, 편성·장비 화면 |
| 탐험 | 이동, 경로 선택, 거점·자원·사건 발견 | 카메라, 이동, 충돌, 상호작용, 월드 생성 |
| 사건 해결 | 교전, 수색, 구조, 목표 달성 | 전투, 퀘스트 조건, 대화 선택 |
| 결과 | 보상 수령, 선택 결과 확인 | 아이템·성장·지역 상태 반영 |
| 귀환·재출발 | 정비, 동료 대화, 진행 저장 | 거점, 관계 기록, 저장·불러오기 |

모든 임무에 귀환을 강제할지, 현장에서 연속 의뢰를 수행할 수 있게 할지는 미정이다.

## 5. 월드와 탐험

### 5.1 필수 요구사항

- 맵 끝에서 탐험이 끊기지 않도록 새로운 영역을 자동으로 생성한다.
- 재방문할 수 있으며 진행·변경 상태가 유지되어야 한다.
- 3D 지형과 고정 각도 카메라에서 이동 경로와 높낮이가 읽혀야 한다.

### 5.2 구현 기본안

월드를 청크로 나누고 플레이어 주변 영역을 준비한다. 경계에 도착하기 전에 다음 청크를 생성하고, 멀어진 청크는 메모리에서 해제한다. 시드와 청크 좌표를 이용해 기본 지형을 재현하고 플레이어의 변경 사항을 별도로 저장한다.

| 데이터 | 관리 방향 |
|---|---|
| 기본 지형 | 시드·청크 좌표·생성 규칙에 따른 재현 |
| 연결 구조 | 청크 경계의 도로·지형·통행 가능 여부를 일관되게 관리 |
| 변경 사항 | 획득한 물자, 완료한 임무, 거점 상태 등을 지속 저장 |
| 고유 콘텐츠 | 주요 NPC·퀘스트 장소에 고유 ID 부여, 중복 생성 방지 |
| 반복 콘텐츠 | 일반 적·자원 등의 재생성 규칙을 고유 콘텐츠와 구분 |

무한 탐험은 게임 시스템의 목표다. 원작 세계가 물리적으로 무한하다고 설정하지 않는다. 장거리 이동에 따른 좌표 정밀도와 저장 용량 증가도 후속 기술 검토 대상으로 둔다.

### 5.3 지역 구성 제안

기지, 민간 거주지, 도로, 숲, 폐공업지대, 중계소 등의 장소를 사용한다. 주요 거점과 이야기 장소는 수작업으로 구성하고 주변 탐험 공간은 절차적으로 생성하는 방식을 제안한다. 지역 목록과 실제 원작 지리와의 대응은 아직 확정하지 않는다.

## 6. 비주얼과 조작

상세 기준과 조사 출처는 [아트 방향과 리소스 적용 기준](ART_DIRECTION.md)에 정리한다. 소녀전선 1편의 원본 리소스를 사용하며, 필드·전투에는 SD 캐릭터, 대화·상세 화면에는 인물 일러스트를 사용하는 안이다. 픽셀 아트 제작·도트화 전제는 폐기한다. 원본 2D 배경과 별도로 실제 3D 지형을 확보·제작해야 하며, 실제 리소스 가져오기와 런타임 연동은 아직 진행하지 않았다.

### 확정 방향

- 배경은 실제 3D 지오메트리로 구성한다.
- 고정 각도 쿼터뷰 카메라를 사용한다.
- 2D 소녀전선 SD 캐릭터와 3D 배경이 조화를 이루는 화면을 목표로 한다.

### 설계 제안 및 미정 항목

- 원본 SD 리소스에 존재하는 애니메이션과 방향을 먼저 확인하고 빌보드 표현에 적용한다. 다방향 애니메이션이 갖춰져 있다고 가정하지 않는다.
- 조명·그림자·안개 등의 분위기 효과는 기본 화면과 가독성을 확보한 뒤 추가한다.
- 건물에 캐릭터가 가려질 때의 처리, 층간 이동, 목표물 선택 방식을 후속 설계한다.
- 카메라 각도·원근/직교 투영·줌·추적 범위, 스프라이트 해상도·방향 수는 미정이다.
- 필드에서 인간 지휘관을 직접 조작할지, 대표 인형 또는 소대를 조작할지 미정이다. 플레이어의 서사적 신분과 조작 대상을 혼동하지 않는다.
- 마우스 클릭 중심 조작과 필요한 키보드 보조 입력을 사용한다. 튜토리얼 키 배치는 TUTORIAL_LEVEL.md의 제안이며, 패드 지원은 미정이다.

## 8. 스토리와 원작 사건

기준 자료는 사용자 제공 요약이며 원작 대사 대조 검증 완료를 뜻하지 않는다. 전쟁·오염 이후 생존과 인형의 자주권을 반영한 [최신 적용 기준](WORLD_AND_STORY.md)이 아래 초기안보다 우선한다. 원작 지휘관의 신상과 결말은 별도 플레이어에게 이전하지 않는다. 후반 비밀은 실제 정보 획득 시점 이후에만 공개한다.

### 확정된 경계

1. 소녀전선 1편의 세계관과 캐릭터를 사용한다.
2. 원작의 주요 사건과 월드 이벤트는 동일하게 진행한다.
3. 플레이어는 원작 지휘관과 별개인 인간 지휘관이다.
4. 시작 소속은 그리폰 & 크루거 PMC다.
5. 회사 잔류 또는 인형들과 독립하는 선택이 가능해야 한다.

### 병행 서사 운영 제안

원작 사건의 공통 진행 상태와 플레이어 개인 퀘스트 상태를 분리한다. 원작 사건의 여파를 보급 상황, 이동 가능 경로, 지역 임무 등에 반영하되, 새로운 사건의 세부 내용은 창작 설정으로 표시한다.

원작 캐릭터의 출현은 그 시점의 소속·위치·임무·관계와 맞아야 한다. 원작에서 다른 임무를 수행 중인 인물을 무조건 상시 동료로 추가하지 않는다.

**시간 진행 방식은 미정이다.** 실제 플레이 시간, 게임 내 날짜, 메인 퀘스트 달성 중 무엇으로 주요 사건을 진행할지 결정해야 한다. 무한 탐험과 원작 사건 진행이 충돌하지 않도록, 우선은 핵심 퀘스트 진행에 맞춰 사건을 여는 방식을 검토할 수 있다.

### 잔류와 독립의 차이 — 제안

| 항목 | 회사 잔류 | 독립 활동 |
|---|---|---|
| 거점 | 회사 기지 | 자체 확보한 거점 |
| 임무 | 회사 작전과 계약 중심 | 직접 고르는 의뢰 중심 |
| 지원 | 조직의 지원과 규정 | 직접 확보한 거래·정비 관계 |
| 주요 갈등 | 상부 명령과 현장 판단 | 자유와 생존 책임 |

분기 시점, 선행 선택, 재합류 가능성, 인형별 동행 의사와 소속·장비 처리는 추가 설계한다. 제공 자료의 최종 협약과 회사 재편이 플레이어의 진로에 미치는 범위도 별도 확인한다.

## 9. 1장 퀘스트라인 — 창작 적용안

사용자 자료 반영 후의 1장 연결은 [WORLD_AND_STORY.md](WORLD_AND_STORY.md)를 따른다. 현재 구현은 중계소의 부품 확보·방어·통신 복구까지이며, 수송차 수색은 대사상 다음 임무 예고다. 아래 초기 초안과 다를 경우 최신 적용 문서를 우선한다.

### 가제: 끊어진 보급선

신임 지휘관이 외곽 전초기지에 부임하고 첫 임무를 수행하며 동료들과 신뢰를 쌓는다. 부족한 지원 속에서 보급 확보, 주민 구조, 인형의 안전 사이에 우선순위를 정한다. 원작의 특정 사건을 대체하지 않는 별도 지역 이야기다.

| 순서 | 퀘스트 | 주요 전개 | 플레이 목적 |
|---|---|---|---|
| 1 | 부임 신고 | 기지와 소대 소개, 보급 목록 불일치 발견 | 이동·대화·시설 이용 |
| 2 | 첫 순찰 | 중계소 점검 중 적 정찰 병력 조우 | 탐험·첫 전투·경로 선택 |
| 3 | 돌아오지 않은 수송차 | 끊긴 보급 차량 연락을 추적, 생존자 흔적 발견 | 수색과 보급 회수의 우선순위 |
| 4 | 임시 대피소 | 부상 운전사와 주민 발견, 주변 공격 정보 획득 | 호위 준비·수송 공간 배분 |
| 5 | 잡음 속의 목소리 | 중계소의 인형 구조 신호 추적, 통신 복구 | 정면 공격 또는 우회 |
| 6 | 마지막 수송 | 증원 전 주민·부상자 철수, 적 접근 저지 | 장의 주요 전투·앞선 준비 반영 |
| 7 | 지휘관의 보고서 | 복귀, 성과·손실 보고, 동료 반응 확인 | 결과 정산·선택의 여파 |

보급 확보는 이후 물자 여유로, 주민 지원은 지역 교류로, 인형의 의견을 대하는 태도는 동료 반응으로 연결하는 안이다. 회사에도 지원이 어려운 사정을 두고, 초반 한 번의 선택으로 동료가 영구 상실되는 구조는 피하는 것을 제안한다.

엔딩에서는 복구한 기록에서 지도 바깥의 구조 요청을 발견하고 인접 구역 정찰 임무를 받아 다음 지역으로 나아간다. 잔류/독립의 최종 결정은 이후 장으로 남기는 안이다.

초기 콘텐츠 공간은 기지 하나, 작은 거주지 하나, 도로·숲·폐공장 구역, 중계소 하나다. 구체적인 지역명, 인형, 적, 대사, 보상, 분기 수치는 모두 미정이다.

## 10. 첫 시제품과 개발 단계

현재 시제품의 범위와 완료 기준은 [5분 이내 튜토리얼 레벨 설계](TUTORIAL_LEVEL.md)를 우선한다. 아래 개발 단계는 본편까지 포함한 장기 로드맵이다. 클릭 조작, 보조 상호작용 키, 분위기 렌더링, 콘발라리아식 실시간 타워디펜스 전투와 작은 퀘스트가 현재 필수 요구사항이다.
### 첫 시각적 시제품

작은 3D 지형을 고정 각도에서 바라보며 소녀전선 SD 캐릭터가 이동한다. 바닥과 벽의 충돌, 확보된 원본에 맞춘 방향 표현과 기본 애니메이션을 확인할 수 있어야 한다.

### 첫 플레이 시제품

현재 시제품은 클릭 이동 → 상호작용 → 실시간 타워디펜스 전투 → 퀘스트 완료가 연결되는 5분 이내 튜토리얼 레벨이다. 상세 범위는 TUTORIAL_LEVEL.md를 따른다. 디스크 저장과 1장 전체는 후속 범위로 둔다.

| 단계 | 개발 범위 | 사용자가 확인할 완료 기준 |
|---|---|---|
| 1 | 기반 안정화 | 오류 원인이 드러나며 필요한 파일·의존성이 정리됨 |
| 2 | 게임 루프와 입력 | 시간 기반 업데이트와 입력 상태가 동작 |
| 3 | 3D 공간·카메라·캐릭터 | 의도한 쿼터뷰 화면에서 캐릭터가 표시·이동 |
| 4 | 탐험과 상호작용 | 충돌이 적용되고 NPC·목표물과 상호작용 |
| 5 | 최소 RPG 흐름 | 임무·전투·보상·저장·재개가 연결 |
| 6 | 청크 확장 | 경계 이동 시 다음 영역 준비, 재방문 상태 유지 |
| 7 | 콘텐츠 확장 | 1장과 진로 분기, 지역 콘텐츠를 점진적으로 추가 |

월드 좌표·청크 좌표·고유 ID·저장 상태는 초반부터 구분한다. 전체 월드 생성이나 복잡한 전투 규칙은 작은 플레이 흐름이 성립한 뒤 확장한다. 청크 실험의 구체적인 순서는 개발 상황에 맞춰 조정한다.

첫 시제품에서는 잔류/독립 전체 분기, 많은 원작 캐릭터, 모든 지역 유형, 고급 후처리까지 요구하지 않는다. 목표 프레임률·최소 사양·로드 시간 같은 정량 기준은 아직 정하지 않았다.

## 11. 현재 상태와 주요 설계 과제

현재 구현은 단색 사각형을 표시하는 OpenGL 기초 코드다. 이 문서의 게임 시스템은 대부분 신규 구현 대상이다.

| 과제 | 진행 방향 |
|---|---|
| 초기화·리소스·경로 문제 | 게임 기능 추가 전 기반 안정화 |
| 무한 탐험에서 콘텐츠 반복 | 고유 임무와 반복 사건의 역할을 분리 |
| 원작 연표와 자유 탐험 충돌 | 주요 사건의 시간 진행 규칙 결정 |
| 원작 인물과 독립 분기 충돌 | 등장 시점·동행 가능한 인물 범위 결정 |
| 2.5D 화면의 이동 가독성 | 작은 맵에서 높낮이·가림·충돌부터 확인 |
| 시나리오와 기능의 범위 확대 | 작은 시제품을 기준으로 단계별 추가 |

빌드·실행과 결과 확인은 특별한 상황이 아니면 사용자가 맡는다. Codex는 구현과 정적 검토를 수행하고, 실행 확인이 필요한 항목을 명확히 전달한다.

## 12. 다음에 결정할 항목

### 초기 구현 전에 우선 결정

1. 클릭 이동은 확정. 필드 조작 대상은 튜토리얼의 대표 인형 방식을 우선 검토.
2. 실시간 타워디펜스 전투는 확정 방향. 시제품의 아군 2기 구성과 세부 규칙은 설계안.
3. 카메라 투영 방식과 사용할 원본 SD 리소스의 형식·애니메이션·표시 크기.

### 스토리·콘텐츠 제작 전에 결정

1. 원작의 시작 시점과 플레이어 작전 구역.
2. 초기 인형 구성과 원작 인물의 등장 범위.
3. 주요 월드 사건을 진행시키는 시간 규칙.
4. 1장 초안의 채택·수정 여부.
5. 잔류/독립 분기의 조건과 이후 운영 방식.

### 이후 확장 단계에서 결정

1. 성장·장비·자원 경제와 패배 규칙.
2. 청크 크기·생성 규칙·재생성·저장 정책.
3. 플랫폼·배포 형태·목표 사양·일정.

미정 항목은 구현 의존성이 생기는 시점에 결정한다. 기반 안정화처럼 독립적으로 진행할 수 있는 작업을 불필요하게 중단하지 않는다.
