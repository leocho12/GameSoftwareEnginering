# NPC AI Implementation Plan

작성: 2026-10-01 · 상태: 구현 전 검토용
기준: [NPC AI Architecture](NPC_AI_ARCHITECTURE.md), 최신 사용자 첨부 29~34절.

## 1. 이번 완료 범위

현재 폴더·NPC·전투·이벤트·저장 구조를 분석하고 Architecture와 구현 계획 두 문서를 작성한다. 이번에는 게임 소스, 데이터 파일, 프로젝트 설정을 변경하거나 빌드·실행하지 않는다. 앞선 미커밋 변경은 보존한다.

이 문서의 모든 신규 클래스·테스트·데이터 경로는 예정 항목이다. 문서 작성 완료가 게임 기능 구현 완료를 뜻하지 않는다.

## 2. 첫 Vertical Prototype

- 기존 일반 RPG와 마을 20명, F6 훈련은 유지한다.
- 기존 마을의 작은 기지 구역을 재사용하며 미라·벨은 시험 동료로 추가하는 안이다. 기존 주민 이름·성격을 임의로 덮어쓰지 않는다.
- 사건은 Missing Doll 하나다. 플레이어 수락 여부와 무관하게 생성·인지·기한·결과가 존재한다.
- BDI, Basic Belief, Utility 목표 선택, 방향성 관계, 기본 Episodic Memory, 시간·사건·원격 시뮬레이션, 조건부 접근 대화, 디버그 UI를 연결한다.
- 미라의 높은 구조 Desire도 데이터로 설정한다. 이름별 구조 강제 분기는 사용하지 않는다. 벨은 관계/위험/능력/기존 의도를 평가해 동행 또는 잔류한다.
- 최초에는 GOAP/HTN 검색 대신 데이터로 정의된 준비→출발→탐색→해결→귀환 작업을 실행한다. 목표 선택과 행동 실행의 경계는 후속 Planner 연결에 맞춘다.

플레이어는 보고를 듣거나 무시하고 자원을 지원할 수 있다. 직접 참여 경로는 출발 전 참여 의도를 같은 사건에 등록하고 기지 인근 수색/구조 상호작용 결과를 공통 Resolver로 전달하는 안이다. 원격 원정 도중 합류·실시간 전투 전환은 첫 범위에서 제외한다.

## 3. 구현 순서와 검토 단위

| 단계 | 추가·변경 내용 | 통과 기준 |
|---|---|---|
| P0 기반 정리 | ActorId/등록소, NPC 영속 상태와 로컬 상태 구분, 관계 중복 해소, 데이터 로더 경계 | 기존 20명/거래/사냥/F6 유지, 인물 ID가 배열 순서에 의존하지 않음 |
| P1 시간·사건 코어 | GameClock, WorldState 최소형, WorldEventSystem, Resolver, 알림 큐, Scheduler, EventJournal | 무입력에도 사건 기한 진행, 효과 1회 적용, Canon 변경 거부 |
| P2 NPC 사고 모델 | NpcBrain BDI, 장기 Belief, Desire 생성, Utility/commitment, 프로필·스킬 데이터 | 모르는 사건에는 반응하지 않음. 조건 변화에 따른 점수·의도 변화 설명 가능 |
| P3 자율 실행 | TaskRunner, 기존 이동 어댑터, 단독/동행 제안, 원격 임무 단계 | NPC가 실제 출구까지 이동 후 원정 상태가 되고 귀환 가능 |
| P4 결과와 경험 | 구조/실패/부상 효과, 방향성 관계, Episodic Memory, 태그 기반 회상 | 상태·기억·관계가 같은 원인 EventId로 추적됨 |
| P5 대화·표시 | 조건 선택지, 목표에 따른 거절/중단, 보고·QuestView·세계 기록, 플레이어 개입 | 미수신 결과 누출 없음. 선택 시점 재검증. 방치와 참여 모두 사건 종료 |
| P6 디버그·검증 | NPC/사건 화면 완성, CPU/큐/판단 로그, 재현·회귀 확인 | 아래 인수 시나리오 통과 후 후속 단계 검토 |

디버그 기록은 P1부터 넣고 UI는 P6에서 완성한다. 중요한 문제를 마지막에만 관측하도록 미루지 않는다. 각 단계는 코드 정적 검토와 사용자 실행 결과를 구분해 기록하며, 실패한 단계를 건너뛰어 다음 기능을 겹쳐 넣지 않는다.

## 4. 기존 파일의 변경 지점

| 파일 | 구현 시 변경 계획 |
|---|---|
| `RpgGame.h/.cpp` | WorldSimulation 소유/갱신 연결, Reset과 시간 정책 연결. 기존 전투 delta와 달력 시간 분리 |
| `TownNpc.h` | 안정 ID 참조, 로컬 이동/전투 상태. Mind/개인 상태의 소유권 이관을 단계적으로 수행 |
| `TownNpc.cpp` | 초기화의 프로필 데이터화, Brain이 지정한 Task 실행, 중요 피해/지원 결과 알림. 기존 즉시 행동 선택기는 비이관 주민의 호환 경로로 유지 |
| `NpcMind.h` | 지식·관계·기억 확장. 영구 이야기 사실과 퇴출 가능한 단기 기억 구분 |
| `TownKnowledge.cpp` | 기존 감지·통신을 Belief 입력 어댑터로 사용. 사건 정보도 수신 경로를 통해 전달 |
| `SimpleGame.cpp` | 새 대화/디버그 입력 전달. 판단 로직은 두지 않음 |
| `RendererTown.cpp`, `Renderer.cpp` | 원정 중 인물 제외, 귀환 위치 표시, 읽기 전용 대화/디버그 모델 사용 |
| `.vcxproj/.filters` | 신규 코어/렌더 소스와 데이터 복사 등록 |
| `tests/` | 기존 회귀 보존, 새 월드·사고 모델·해결/재생 검사 추가 |

코어는 Windows/OpenGL을 포함하지 않는다. 기존 시스템을 한 번에 전부 옮기지 않고 미라·벨부터 Brain/TaskRunner 경로에 연결한다. 호환 경로와 신규 경로가 같은 인물을 동시에 갱신하거나 치료/피해를 중복 적용하지 않게 명시적인 실행 권한을 둔다.

## 5. 첫 사건 상태 흐름

1. 사건 생성: 안정 EventId, 위치, 실종 대상, 시작/기한, 위험·필요 자원 정의.
2. 정보 전달: 구조 신호 수신자에게 출처·시각·신뢰도가 있는 Belief 생성. 인지하지 못한 인물은 후보를 만들지 않는다.
3. 의도 결정: 구조/정보 수집/대기/기지 유지 후보와 기여점수 계산. 중요한 선택은 난수로 결정하지 않는다.
4. 협력: 미라의 동행 요청을 벨이 자신의 Brain으로 평가. 초기에는 두 인물 간 요청/응답만 구현하며 범용 Contract-Net이라고 부르지 않는다.
5. 준비/이동: 물자 예약과 실행 가능 여부 확인. 막힌 출구는 재시도 제한 후 실패 사실을 Brain에 반환한다.
6. 원격 진행: 출구 도달 후 실제 길찾기/전투 없이 시각순 예약 사건으로 도착·탐색·조우·결과를 처리한다.
7. 결과 커밋: 자원·구조 인원·부상/생명 상태 변경을 단 한 번 적용하고 Journal/알림 생성.
8. 귀환/보고: 생존자는 다시 배치하고 부상자는 치료 위치로 이동. 직접 경험과 전달받은 정보에 따라 기억·대사 생성.
9. 무대응: 누구도 출발하지 않아도 기한 결과가 발생한다. 실패는 다음 지역 상태이며 무조건 게임 오버로 처리하지 않는다.

사건 해결 시각과 귀환 시각은 다르다. 플레이어가 결과를 알게 된 시각도 별도로 유지한다. 죽은 인물이 현재 주민의 30초 회복 규칙으로 되살아나지 않아야 한다.

## 6. 시간·데이터·저장 정책 제안

- 전투는 기존 Step을 유지한다. GameClock은 정수 시각을 사용하고 달력 배율은 설정값이다. 실제 1초=게임 1분은 시험용 시작안이며 확정 밸런스가 아니다.
- 테스트용 다음 예약 사건까지 진행 기능을 제공한다. 시간을 건너뛰어도 예약 사건은 시각/안정 ID 순으로 처리하며 예산 초과분을 다음 틱에 보존한다.
- 일시정지·F6 독립 훈련·종료 중 월드는 정지하는 것이 첫 정책이다. 종료 중 오프라인 진행은 포함하지 않는다.
- 성향·목표·대화·사건·작업 순서는 검증 가능한 JSON 데이터로 분리한다. JSON 라이브러리 선택과 배포 경로는 P0에서 확정한다.
- 최초 Journal은 메모리 기반이며 진단 JSONL과 별개다. 중요한 상태 전이는 reducer로 재생 가능하도록 한다. 전체 사격 프레임을 영속 기록하지 않는다.
- 저장/불러오기는 별도 단계로 문서화하고 장기 플레이 확대 전에 적용한다. 버전/마지막 sequence/진행 원정/예약 자원/Brain/기억/관계/Belief/시계/RNG 상태를 함께 저장한다. 로드 시 확정 결과를 재추첨하거나 중복 보상하지 않는다.

## 7. 검증 계획

C++ 테스트 소스를 구현 단계에서 추가한다. 빌드·게임 실행은 기존 사용자 지침대로 사용자가 담당한다.

| 검사 | 기대 결과 |
|---|---|
| 플레이어 방치 | 인식→Belief→Desire→Intention→출발→해결→귀환→대화 변화 |
| 잘못된 정보 | 잘못된 위치 보고를 믿어 우회 가능. 진실 발견 후 믿음 수정. 판단 이유에서 사용 사실 확인 |
| 통신 부재 | 수신하지 않은 인물은 같은 사건을 자동으로 알지 못함 |
| 관계 변경 | Mira→Bell과 Bell→Mira가 독립. 벨의 동행 점수/결정 변화가 설명됨 |
| 목표 안정성 | 작은 점수 변동에 의도 반복 전환하지 않음. 긴급 위험/불가능 상태에서는 중단 |
| 원격 실행 | 화면 밖 BFS·매 프레임 Combat 호출 없음. 귀환 위치와 상태 정상 |
| 무대응/실패 | 기한 만료 후 사건 종료. 부상/실패의 기억·관계·대사 갱신 |
| 중복/경합 | 플레이어와 NPC의 동시 구조, 반복 알림, replay에서도 효과 한 번 적용 |
| 대화 | 중요 목표 수행 중 거절/중단, 선택 직전 조건 재검사, 미인지 결과 비공개 |
| 기억 감쇠/회상 | 약한 기억 감소, 중요 기억 보존, 태그 유사도와 기여 추적 |
| 재현 | 동일 seed/초기 데이터/의도 순서에서 동일 결과. 렌더 FPS 변화에 영향 없음 |
| 회귀 | WASD·공격·경험치·거래·기존 주민·F6 유지 |
| 데이터 오류 | 잘못된 ID·참조·필수값·수치 범위를 로드 시 식별 |

디버그 필수: Belief와 출처/신뢰도, Desires, Intention, Utility 기여값, commitment/전환 이유, 실행 Task, 사건 상태/기한/참여자, 중요 기억/방향성 관계/최근 결정. 미구현 GOAP/HTN/감정/전략은 명확히 미구현으로 표시한다.

성능 필드 제안: `cpu_perception_ms`, `cpu_goal_eval_ms`, `cpu_task_ms`, `cpu_resolution_ms`, `cpu_log_write_ms`, `scheduled_events`, `processed_events`, `deferred_events`, `active_npcs`, `path_replans`. 틱당 최대값과 p95를 비교하고 하위 구간을 전체 시간과 중복 합산하지 않는다. 평상시 상태 변화만 기록하고 상세 후보 덤프는 선택 NPC에 제한한다.

## 8. 프로토타입 이후 확장 순서

최신 첨부의 순서를 따른다. 이전 계획의 확장 순서를 이 목록으로 대체한다.

1. **Blackboard:** 통신/거리/재밍/데이터 링크별 전달·만료. 로컬 믿음과 공유 사실 분리.
2. **Role Bidding / Contract-Net:** 다중 작업 제안·입찰·예약·수락·취소·만료. 능력/장비/현재 작업 포함.
3. **GOAP:** 제한된 전술 액션 집합, 확장 노드/시간 예산, 계획 실패와 재계획.
4. **HTN:** 장기 목표의 조건별 방법 분해, 필요할 때 GOAP 하위 작업 호출.
5. **Influence Map:** 알려진 위협·지원·엄폐·사선·탈출 안전. 탐색과 갱신 범위 제한.
6. **Storylet:** 일과·개인 이야기·감정 입력을 필요한 만큼 추가하고 플레이어 부재에서도 사건 진행.
7. **Social Imitation:** 기존 소규모 성향 변화를 관측 성공·관계·경험·피드백·저항 기반으로 확장.
8. **Steady-State GA:** 전략 population만 임무 종료 때 소수 교체. 성격 원형과 가중치 변화량 보호.
9. **AI LOD:** 3단계 갱신·전환·예산 조정. 첫 버전의 단순 원격/근거리 구분을 범용화.
10. **Regional World Simulation:** 복수 지역과 공급·치안·영속 사건 확대.
11. **Faction AI:** 같은 사건 요청/해결 계약을 사용하는 세력 의사결정.

각 단계는 독립 완료 조건과 검사 결과가 있어야 다음으로 넘어간다. 첫 원격 Scheduler는 필수 기능이며, 전체 AI LOD 체계가 구현되었다는 의미는 아니다.

## 9. 검토 후 구현을 시작할 첫 단위

P0~P1의 **안정 ActorId + GameClock + 사건 하나의 생성/기한/단일 해결**부터 시작한다. 그다음 기존 NpcMind에 BDI를 연결한다. 상속 계층이나 모든 알고리즘의 빈 클래스를 먼저 생성하지 않는다.

본편 연도/기지명/시험 인물의 최종 설정, 영구 사망 정책, 시간 배율은 미정이다. 시험 데이터와 정책으로 격리하며 원작 세계관의 확정 사실로 취급하지 않는다.

## 2026-10-01 첫 구현 반영

[실제 반영 범위와 조작](NPC_WORLD_PROTOTYPE.md)을 참조한다. 안정 ID의 별도 두 동료, 달력·사건·BDI 목표·원격 처리·지역 효과·기억/관계·대화·디버그를 연결했다. 평면 데이터는 외부 의존성 없이 검증하기 위해 TSV로 구현했다. 전체 Manager 분리, 모든 기존 NPC 이관, 범용 EventBus/전체 replay/영속 저장·GOAP·HTN은 미구현이다. 테스트 소스는 작성했으나 C++ 빌드·실행은 사용자 확인 전이다.
