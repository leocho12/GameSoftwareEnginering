# ADBS Phase 1 — Doll 2명과 구조 상황 1개

사용자 첨부 ADBS 설계의 최소 단계만 구현한다. 유전 알고리즘·전략 개체군·Fitness·모방·Commander Profile·소대 문화·Save/Load는 구현하지 않았다. 반복 실행만으로 Trait가 학습되지 않는다. 20회 임무 후 학습 분화는 이번 단계의 검증 목표가 아니다.

## 플레이 방법

- 사냥터에서 **F6**: 별도 구조 훈련 진입/복귀. 사냥터 상태·경험치·적은 훈련 중 진행하지 않는다. 훈련에서는 플레이어 이동·직접 공격 대신 지휘와 관찰을 한다.
- **1** 구조 명령, **2** 대기 명령, **3** 명령 해제.
- **R** 같은 Trait로 재시도, **Tab** 두 인형의 구조/부상 역할 교환 후 재시도.
- **[ / ]** 구조 담당자의 Trait 선택, **- / +** 0.1 조절, **0** 두 인형의 기본 Trait 복원.
- **Esc** 정지/계속. 포커스 이탈 시에도 기존 정지 동작을 따른다.

Doll A와 Doll B는 원작 성격과 무관한 가상 시험 인형이다. 기존 M4A1/UMP45 SD는 구분 가능한 시험 외형으로만 쓴다. 원작 스토리 이벤트를 추가하지 않는다.

## 최소 시나리오

총 Doll은 정확히 2명이다. 한 명은 구조 담당, 다른 한 명은 체력 50의 부상자다. 항상 같은 장애물 없는 7×7 훈련 바닥을 사용한다. 무작위 맵 경로 문제와 AI 판단 문제를 분리한다.

부상자는 처치 전 초당 체력 2를 잃는다. 모의 위협 강도는 0.8이며 구조 담당자에게 지속 피해를 준다. 빨간 원이 위협 위치다. 공격하면 위협이 줄어든다. 파란 엄폐 구역에서는 엄폐 행동으로 피해를 줄이고 회복한다. 녹색 원은 이송 지점이다. 별도 적 개체·민간인·전투 보상은 없다.

구조 행동은 접근 → 1.5초 처치 → 안전 구역까지 이송이다. 처치 완료부터 출혈이 멈춘다. 이송 중에는 구조를 유지해 행동 전환으로 환자를 떨어뜨리지 않는다. 나머지 구간은 명령/점수 변화로 중단될 수 있다. 도중 이탈 후 처치 재개 시 거리와 처치 시간을 다시 확인한다. 구조 성공, 부상자 손실, 구조자 전투불능, 35초 초과, 사용자 재시작/종료 중단을 기록한다.

## Trait와 Utility

값 범위는 0~1이며 아래 5개만 있다.

| Trait | 역할 | A | B |
|---|---|---:|---:|
| aggression | 위협 제압 점수 | .25 | .55 |
| coverPreference | 엄폐·후퇴 선호 및 위험한 구조의 감점 | .55 | .70 |
| rescuePriority | 동료 구조 점수 | .90 | .45 |
| commandObedience | 구조 명령 가산 / 대기 명령 가산·구조 감점 | .55 | .90 |
| autonomy | 자율 구조 허용과 구조 점수 | .85 | .20 |

0.25초 간격으로 대기·공격·엄폐·구조·후퇴 점수를 계산한다. 자율성 > 0.70 또는 구조 명령이 있을 때 구조 후보를 허용한다. 조건 미충족 후보 점수는 -1이다. 최고 점수 행동을 선택하되 점수차 0.08 미만은 이전 행동을 유지한다. 엄폐는 체력 90 미만, 후퇴는 체력 35 미만일 때 후보가 된다. 가중치는 초기 실험값이며 정답 성격을 규정하지 않는다.

기본 A는 명령 없이 구조 성공, 역할을 바꾼 기본 B는 위협 제압 후 구조 명령 없이 기다리다 부상자 손실이 예상된다. B에게 1을 누르면 구조 가능하다. 이것은 학습 결과가 아닌 초기 Trait 차이와 실제 Utility 판정 결과다. 화면에 두 인형의 Trait와 행동 점수를 함께 표시한다.

## AI 판단 로그

실행 파일 옆 `Profiles/adbs.jsonl`에 JSONL로 기록한다. 5 MiB를 넘으면 `adbs.previous.jsonl`로 순환한다. 현재/이전 파일만 유지하며 로그 저장 실패가 플레이를 막지는 않는다.

주요 필드: `schema_version`, `system=adbs_phase1`, `session_id`(UTC Unix ms), `sequence`, `round`, `event`, `elapsed_s`, `rescuer_id`, `command`, `action`, `result`, `rescue_phase`(0 접근/1 처치/2 이송), `selection_reason`, `rescue_unlocked`, `utility_scores`, 두 인형의 위치·체력·Trait, `report`.

판단 이유는 `max_utility`, `switch_hysteresis`, `evacuation_commitment`로 구분한다. 행동 점수 -1은 수행 불가이지 부정적 학습 보상이 아니다. `decision`은 약 4Hz, 명령·Trait 변경과 구조 단계 전환·종료는 이벤트마다 기록한다. 종료 시 flush하며 강제 종료하면 마지막 버퍼 일부는 남지 않을 수 있다.

Report는 구조 횟수, 자율 구조 진입 수, 명령과 다른 행동으로 전환한 횟수, 피해·위험 노출·공격 시간, 판단 횟수·누적 판단 CPU ms·누적 Update CPU ms다. Update 시간에는 대부분의 로그 쓰기가 포함되고 최종 결과 로그 쓰기는 제외된다. 점수·시간·실행 결과를 연결하는 Phase 1 계측이며 학습 평가 Fitness는 아니다.

## 확인 항목과 상태

- A 자율 구조 성공 / B 무명령 시 부상자 손실 / B 구조 명령 시 성공.
- 대기→구조 명령 전환, 0~1 Trait 제한, 역할 교환, 재시작 보고서 초기화.
- 이송 완료가 한 번만 기록되는지, F6 복귀 후 사냥터 상태가 보존되는지.
- 정지·포커스 이탈 시 AI 시간/출혈도 정지하는지.

`tests/DollBehaviorTests.cpp`에 순수 CPU 회귀 검사를 작성했다. 별도 컴파일 시 `DollBehavior.cpp`를 함께 포함한다. 기존 RpgGame CPU 테스트도 이제 `DollBehavior.cpp`를 링크해야 한다. 사용자 요청에 따라 게임 및 C++ 테스트 빌드·실행은 하지 않았다. 화면·애니메이션·실제 행동 결과는 사용자 실행 확인 대상이다.
