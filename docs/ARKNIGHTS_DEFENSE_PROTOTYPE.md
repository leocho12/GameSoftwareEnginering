# 명일방주 전투 분석과 방어전 프로토타입

작성: 2026-09-10. 사용자 요청에 따라 기존 턴제 전투를 대체한다. 세계관·캐릭터 아트는 소녀전선 1편이며, 명일방주는 전투 시스템의 참고 대상이다. 아래 구현 수치는 원작의 수치가 아니라 이 프로젝트의 튜토리얼용 설계다.

## 조사 결과

명일방주의 기본 전투는 적의 출현 지점과 보호 목표 사이에 오퍼레이터를 배치하는 실시간 방어전이다. 적의 이동 경로와 배치 비용, 병과 역할을 읽고 방어선을 구성하며, 자동 전투 도중 스킬과 퇴각을 판단한다. 근접 공격·방어·원거리 공격·회복 역할이 서로 보완된다. [GameWith 기본 전투 가이드](https://gamewith.net/arknights/article/show/14985) — 공식 문서가 아닌 공략 자료이며 기본 규칙 확인에 사용했다.

저지는 사거리와 별개의 개념이다. 적을 멈출 수 있는 수가 제한되므로 공격력이 충분하더라도 저지 능력을 초과하면 적이 통과할 수 있다. 저지된 적은 방어 유닛을 공격한다. [Arknights Wiki 저지 설명](https://arknights.fandom.com/wiki/Attribute/Block) — 팬 위키.

배치 방향은 공격 범위를 결정하며, 병과·캐릭터에 따라 사거리 형태가 다르다. 원작에는 배치 비용과 재배치 대기 상태를 보여주는 UI가 있고, 선택한 유닛의 공격 범위와 기술 정보를 확인한다. [Terra Wiki 작전 설명](https://arknights.wiki.gg/wiki/Operation) — 검색으로 확인한 팬 위키 요약; 본문 접근은 차단되어 전체 내용을 검토하지 못했다.

퇴각은 비용 일부를 돌려받는 대신 재배치 대기와 재배치 비용 증가를 수반하는 전략적 선택이다. [Terra Wiki 고급 전략](https://arknights.wiki.gg/wiki/Advanced_strategies) — 검색으로 확인한 팬 위키 요약.

## 이 프로젝트에 적용한 규칙

| 시스템 | 구현 |
|---|---|
| 전투 진입 | 필드의 중계소 마당 진입 또는 야생 개체 조우 → 별도 방어전 보드 |
| 공간 | 필드와 전투 모두 3D 지오메트리 + 고정 각도 2.5D 쿼터뷰 |
| 승리 | 모든 적이 처치 또는 돌파로 처리되고 거점 내구도가 남음 |
| 패배 | 적 5기 돌파로 거점 내구도 0. 조우부터 재도전 |
| 배치 비용 | 초기 24, 초당 1 회복, 최대 99 |
| 인원 | 네 역할 각 1기, 동시 배치 최대 4 |
| 배치 | 카드 선택 → 유효 타일 → 바라볼 방향의 다른 타일 클릭. F 회전·Enter 확정도 지원 |
| 지형 | 선봉·방패는 지상, 소총·수리는 고지. 입구·출구 열은 배치 불가 |
| 공격 | 전방 사거리 내 거점에 가까운 적을 자동 공격. 자신이 저지한 적은 방향과 무관하게 공격 가능 |
| 회복 | 수리 인형은 사거리 내 체력 비율이 가장 낮은 배치 아군을 자동 수리 |
| 저지 | 선봉 1, 방패 3. 초과 개체는 계속 이동. 저지 중 적의 반격 발생 |
| 기술 | 배치 시 충전 10, 최대 20, 초당 1 충전. 수동 Q, 지속 기술 중 충전 중단 |
| 퇴각 | 현재 배치 비용의 50% 반환, 20초 대기. 전투 불능은 반환 없음 |
| 속도 | 1배/2배속, 전술 정지, 별도 Esc 메뉴 정지 |
| 필드 복귀 | 조우 직전 위치·부품 상태 보존. 필수 방어 성공 후 단말 복구, 야생 방어 성공 후 탐험 |

원작과 다르게 재배치 비용은 증가하지 않으며, 전술 정지 중 배치·기술·퇴각 지시를 허용한다. 전투 시간은 소규모 튜토리얼에 맞춰 축소했다. 마법·공중 적·특수 병과·가챠·캐릭터 성장·자동 재현은 구현하지 않았다. 고지 유닛의 범위는 전방 3칸과 좌우 1칸을 기본으로 단순화했다.

## 편성과 튜토리얼 수치

| 인형(임시 명칭) | 비용 | 체력 | 역할 | 기술 |
|---|---:|---:|---|---|
| 선봉 인형 | 8 | 100 | 저지 1, 빠른 초기 대응 | 배치 비용 +10 |
| 방패 인형 | 12 | 240 | 저지 3, 합류 지점 방어 | 8초간 받는 피해 70% 감소 |
| 소총 인형 | 14 | 90 | 고지 원거리 공격 | 8초간 공격력 1.8배 |
| 수리 인형 | 10 | 90 | 고지 아군 회복 | 8초간 수리량 2배 |

전투 시작 후 10초 준비, 4초마다 한 기씩 총 12기 출현. 두 진입로가 합류하여 같은 거점에 도착한다. 일반 적과 더 느리고 튼튼한 장갑 적을 혼합한다. 외곽 야생 조우는 같은 규칙에 8기를 사용하며 야생 외형으로 표시한다. 이는 원작 스토리상의 사건이 아닌 시제품용 조우 구성이다.

필드 이동·부품 확보 30~60초, 방어전 60~120초, 단말 복구 15~30초를 설계 목표로 삼는다. 실제 클리어 시간과 난이도는 사용자 플레이로 확인해야 한다.

## 화면 개선

- Windows DPI 인식을 창 생성 전에 설정하여 OS의 저해상도 창 확대를 방지한다.
- 초기 창은 최대 1920×1080을 목표로 작업 영역 안에 맞춘다. F11 전체화면에서는 모니터 크기를 사용한다.
- 장면 버퍼는 현재 창 픽셀 크기를 따른다. 1280×800은 UI 배치용 좌표계이며 내부 렌더 해상도 제한이 아니다.
- 글자는 표시 크기와 창 크기에 맞춰 다시 래스터화하고 텍스처 캐시를 크기별로 분리한다. UI는 장면 후처리 뒤에 그린다.
- 임시 캐릭터는 128×160에서 512×640으로 확장하되, 기존 비트맵 확대가 아니라 도형을 고해상도로 다시 그린다. 기본 카메라도 가까워졌다.
- 후처리의 인접 픽셀 평균 혼합과 캐릭터 알파 절단을 줄였다.

원작 SD 파일은 여전히 미보유 상태다. 위 변경은 임시 그림의 선명도 개선이며, 원작 아트 품질을 확보했다는 뜻은 아니다. 현재 아군 역할별 외형은 두 임시 그림을 공유하며 이름·역할·범위 표시로 구분한다.

## 코드 및 확인 상태

- `TowerDefense.h/.cpp`: 렌더링과 독립된 방어전 상태·시뮬레이션.
- `TutorialGame.h/.cpp`: 필드·퀘스트와 전투의 진입/복귀.
- `Renderer.h/.cpp`: 방어전 보드·배치 UI·범위·입구/출구·경로·체력 표시.
- `RenderEffects.h/.cpp`, `SimpleGame.cpp`: 글꼴·스프라이트·DPI·창 크기·입력.
- Visual Studio 프로젝트와 필터에 새 파일 등록.
- `tests/TowerDefenseTests.cpp`: 배치 제한, 취소 비용, 퇴각, 전술 정지, 충전, 방향, 저지 초과, 회복, 패배, 자원 내 편성의 승리 시나리오. 사용자가 필요할 때 실행하는 CPU 회귀 검사이며 게임 프로젝트에는 포함하지 않았다.

이번 작업에서는 빌드·게임 실행·회귀 검사 실행을 하지 않았다. 정적 소스 검토와 프로젝트 XML 확인까지만 수행했다. 무한 청크 생성과 본편 성장은 후속 범위다.
