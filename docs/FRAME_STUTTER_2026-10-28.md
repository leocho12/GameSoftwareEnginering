# 프레임 끊김 조사와 수정

2026-10-28. 기존 사용자 실행 로그를 읽고 렌더링·NPC 진단 비용을 수정했다. 게임 자체를 새로 실행해 끊김을 재현한 것은 아니다.

## 관찰한 병목

`Profiles/resource_render.jsonl` 마지막 60개 기록(게임 시간 15.50~77.74)의 CPU 스키닝·업로드 중앙값은 **64.05ms**, p95 **74.55ms**였다. 신규 청크가 없는 기록 54개만 골라도 중앙값 **63.91ms**였다. 따라서 지형 생성 순간만의 문제가 아니라 동적 메시 준비 자체의 지속 비용이 있다.

환경 처리의 기록창 내 최고값은 최대 **251.87ms**, p95 **45.52ms**였고 신규 청크가 있는 기록창이 6개였다. 마지막 부분에서도 새 청크가 몰릴 때 **55.35ms**가 기록됐다.

NPC `performance_window` 최신 seed 2349535926의 5개 기록에서는 판단 시간 중앙값 **154.69ms/기록창**, 전체 갱신 **210.14ms/기록창**이었다. 기존 판단 타이머 안에는 상세 JSON 로그 작성까지 들어 있으므로 순수 AI 계산 비용이라고 해석하면 안 된다.

이 수치는 사용자 실행의 프로파일이며, 실제 벽시계 FPS·전체 프레임 시간·GPU 시간은 아니다. 로그의 프레임 수는 시뮬레이션 시간 기반 창에 포함된 수라 실제 FPS로 환산하지 않았다. 프로세스 전체 CPU·최대 메모리·cold/warm 과업 비교는 측정하지 않았다.

## 소스에서 확인한 원인과 변경

### 1. 배치 배열의 반복 재할당

기존 `Append`는 모델 하나를 붙일 때마다 `reserve(현재 크기 + 모델 크기)`를 호출했다. 필요량만큼 용량이 늘면 모델 수가 늘어날 때 이미 합친 대형 정점/인덱스 배열을 계속 다시 복사할 수 있다. 이 경로는 동적 캐릭터 배치와 정적 청크 생성이 함께 사용한다.

공통 Append 경계에서 부족할 때만 기하급수적으로 용량을 늘리도록 바꿨다. 동적 배치의 기존 저장 공간은 프레임 사이에 재사용한다. 메시·삼각형·NPC 수를 줄이지 않았다.

### 2. 같은 포즈의 스키닝을 캐릭터마다 반복

같은 모델과 같은 애니메이션 시간으로 움직이는 주민도 종전에는 매번 뼈 행렬을 표본화하고 정점마다 4웨이트 스키닝을 다시 했다.

이제 한 번의 actor build 안에서 **모델 identity·클립·클립 시간·이전 클립/시간·전환 혼합값**이 같은 경우 로컬 좌표의 스키닝 결과를 공유한다. 위치·회전·크기 변환은 캐릭터마다 따로 적용한다. 전환 완료 후에는 결과에 영향 없는 이전 클립 정보를 키에서 제외한다.

키 검색 범위는 현재 build에서 실제 계산한 항목뿐이다. 다음 build에서는 범위를 초기화하고 저장 공간만 재사용한다. 씬/seed 초기화 때 항목과 모델 포인터를 모두 버린다. 원본 리소스·클립 시간·전환 보간·법선·그림자/컬러 패스 재사용 방식은 유지한다. 저속 애니메이션 갱신이나 멀리 있는 주민 제거를 도입하지 않았다.

### 3. 청크 경계에서 캐시 생성이 몰림

화면에 꼭 필요한 청크는 계속 모두 준비한다. 그 외에는 기존에 허용하던 한 청크 두께의 보존 영역 안에서 가까운 미생성 청크를 **프레임당 최대 1개** 미리 만든다. 이동 후 갑자기 한 줄 전체를 만들어야 하는 경우를 줄이려는 변경이다.

기존 캐시의 범위 밖으로 메모리 보존 한도를 늘리지 않는다. 첫 로드나 큰 줌 변경에서는 필요한 새 청크를 즉시 만드는 비용이 여전히 발생할 수 있다. 화면에 필요한 지형을 생략해서 FPS를 높이는 방식은 아니다.

### 4. 매 판단마다 동기식 상세 로그

NPC의 판단·이동 주기는 유지했다. 같은 행동을 유지하는 동안의 상세 `decision` 스냅샷만 NPC당 최대 5초 간격으로 남기며, 행동이 바뀌면 즉시 남긴다. 상호작용·치료/사냥 결과와 성능 기록도 계속 남는다. 모니터의 현재 상태 스냅샷은 별도로 유지한다.

판단 CPU 시간은 상세 로그 작성 전에 확정하고, 로그 비용은 `cpu_log_ms`로 분리했다. 따라서 새 `cpu_decision_ms`를 옛 숫자와 그대로 비교하면 안 된다. 전체 갱신 비용과 로그 비용을 함께 봐야 한다.

## 검증한 것

- 변경한 `WorldResources.cpp`와 `TownNpc.cpp`를 MSVC C++17로 독립 컴파일했다.
- `tests/WorldResourcesSkinTests.cpp`를 독립 CPU 검사로 빌드·실행해 통과했다. 실제 새 `Skin` 코드를 호출해 클립/시간/모델별 키 구분, 전환 보간과 완료된 전환의 공유, 다중 웨이트 위치/법선, 프레임/씬 초기화를 검사한다. NDEBUG가 정의되면 빌드를 거부해 assert가 사라진 거짓 통과를 막는다.
- 독립 검사에서는 `WORLD_RESOURCES_CPU_TEST_STUBS`로 미사용 월드 의존성을 연결했다. 이 함수들은 호출되면 즉시 중단하므로 지형·NPC 실행을 가짜 성공으로 대체하지 않는다. 게임 창·OpenGL 컨텍스트를 만들지 않는다.
- 독립 검사 빌드/실행은 이번 성능 회귀 조사에 한한 검증이다. 전체 게임 빌드와 게임 실행은 수행하지 않았다.

## 재빌드 후 확인할 것

Visual Studio에서 현재 프로젝트를 다시 빌드한 뒤 같은 카메라·같은 지역에서 이동해 비교해야 한다. 실행 중이던 이전 바이너리에는 이 소스 수정이 반영되지 않는다.

새 resource_render 필드:

- `skin_evaluations`, `skin_cache_hits`, `skinned_vertices`: 실제 스키닝 횟수·공유 횟수·변형 정점 수.
- `cpu_pose_evaluation_ms`: 스키닝 계산.
- `cpu_actor_assembly_ms`: 캐릭터별 변환과 배치 조립.
- `cpu_actor_upload_ms`: 동적 버퍼 업로드.
- 기존 `cpu_skinning_and_upload_ms`: 전체 동적 배치 준비 시간으로 유지.

아직 수정 후 게임에서 FPS 개선량·GPU 병목·프레임별 지연 분포를 측정하지 않았다. 이번 변경이 모든 끊김을 해결했다고 단정하지 않는다. 새 필드로 계산/조립/업로드 중 남은 병목을 구분할 수 있다.
