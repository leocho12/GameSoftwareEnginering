## 배치와 판단

기존 적 32명·개별 8초 재생성·거리만으로 무조건 추적하는 방식을 폐기했다. 현재는 **3명씩 3개 무리, 최대 9명**이다. 마을 주민 20명과 기존 서사 동료는 유지한다.

- 야영지는 플레이어와 18~32 거리의 이동 가능 지면에 배치한다. 야영지 간격은 13 이상이며 마을 출입로에 붙이지 않는다. 무리는 야영지 주변 3 거리의 공통 순찰 지점을 따라 느슨한 대형으로 이동한다.
- 전멸한 무리는 45초가 지나고 플레이어가 야영지에서 36보다 멀어져야 재배치한다. 생존 무리 전체가 플레이어에서 42보다 멀어진 경우 탐험 지역에 무리 전체를 재배치한다. 전투 중 개별 사망자는 보충하지 않는다. 영속 야영지 저장은 아직 없다.
- 약 0.5초마다 거리 7 이내 플레이어를 시야 검사로 확인한다. 마지막 확인 위치는 5초 기억하며 벽 너머의 정확한 현재 위치를 계속 추적하지 않는다.
- 공격성·위험 감수·자기보존, 주변 같은 무리의 생존자, 경비·사냥꾼, 자신의 체력과 플레이어 공격력을 반영해 순찰·관찰·공격·후퇴·복귀의 Utility 점수를 비교한다. 작은 점수 차이는 기존 행동을 유지하며 체력 25% 미만에서는 위협을 기억하는 동안 후퇴한다.
- 신중한 무리는 관찰하고 공격적인 무리는 우세할 때 선제공격한다. 플레이어가 먼저 공격하면 같은 무리의 거리 8 이내 동료가 12초 동안 피격 대응 정보를 공유한다.
- 야영지에서 14보다 멀어지면 추적을 풀고 복귀한다. 마을 경계 자체를 이동·공격 금지선으로 사용하지 않는다.
- 경비·사냥꾼은 실제 교전 중인 야적을 관측해 대응하며 모든 중립 순찰을 자동 사냥하지 않는다.

`RpgBandits.cpp`에서 기존 NPC의 성향 자료와 충돌을 검사하는 캐시 경로 이동을 재사용한다. 사회적 관계·서사 인격은 복사하지 않는다. 현재 야적은 거리 0.85의 근접 공격이다. 원본 총기 모션과 실제 사거리의 차이는 시험 외형 적용의 한계이며 원작 전투 능력 재현은 이번 범위가 아니다.

## 첫 레벨 목표

1. **레벨 3 달성**: 기존 성장 기준으로 누적 경험치 100, 플레이어 처치 5회.
2. **E로 아이템 2개 회수**: 시작 위치 아이템과 앞 단계에서 직접 주운 아이템도 인정한다. 거래·자동 보상은 제외한다.
3. **마을 경비에게 F로 복귀 보고**: 부품 5개를 한 번 지급하고 자유 탐험을 계속한다. I로 성장 능력치를 확인한다.

상단 패널에 단계·진행 수치·다음 조작·가까운 무리의 화면상 방향과 거리를 표시한다. 기존 레벨 5 안내를 대체하며 원작 본편 1장 스토리를 확정하는 변경은 아니다. N/Enter 재시작 시 진행과 보상을 초기화한다.

## 리소스

원본 경로는 `C:/Users/leoch/Desktop/kr.txwy.and.snqx/files/Android/New`다.

| 용도 | 게임용 리소스 | 적용 |
|---|---|---|
| 플레이어 | 4type | 기존 인간 지휘관 시험 외형 |
| 주민·서사 동료 | m4a1 / ump45 / hk416 / g11 | 창작 이름·직업·성격을 유지하며 원작 SD 공유 |
| 야적 구성원 | guard / ripper / jaeger | 이번에 추출·변환한 원작 적 SD, 야적 행동 시험 외형 |

원작 적 SD를 사용하는 것이 원작 철혈 세력을 창작 야적과 동일시하는 설정 변경은 아니다. 고유 주민 SD 20종이나 인간 야적 전용 아트를 확보한 것은 아니다. 확인한 NPC-People 파일은 대화용 전신 일러스트여서 필드 SD로 쓰지 않았다.

`AssetsSource/GFL/{guard,ripper,jaeger}`에 원본과 SHA-256을 보존한다. 게임용 PNG·GFA는 `BaseProject_SE/SimpleGame/Assets/GFL`에 있으며 기존 빌드 후 복사 규칙을 그대로 사용한다. 대기·이동·공격을 실제 상태와 연결했다. 주민 전투 불능은 죽음 모션의 완전 투명 종료를 피하기 위해 낮춘 대기 자세를 사용한다. 로드 실패 시 기존 임시 스프라이트로 대체하고 콘솔에 오류를 남긴다.

재생성:

```text
python tools/extract_gfl.py <Android/New 경로> AssetsSource/GFL guard ripper jaeger
node tools/convert_gfl.cjs AssetsSource/GFL/guard/Guard.skel AssetsSource/GFL/ripper/Ripper.skel AssetsSource/GFL/jaeger/Jaeger.skel
python tools/bake_gfl.py AssetsSource/GFL BaseProject_SE/SimpleGame/Assets/GFL --models Guard Ripper Jaeger
```

베이크는 선택 모델의 실제 클립만 내보내며 기존 manifest 항목을 보존한다. [적 SD 미리보기](asset-previews/bandits-contact-sheet.png)는 오프라인 합성이며 게임 실행 결과가 아니다.

## 로그와 검증

`Profiles/bandit_ai.jsonl`에 약 1 시뮬레이션 초마다 기록한다. `bandit_performance_window`는 CPU 갱신·경로 시간과 판단·재탐색 횟수를 창당 한 번 기록한다. 경로 시간은 갱신 시간에 포함되므로 합산하지 않는다. 주민·야적 경로는 따로 집계한다. `bandit_ai_snapshot`은 개체별 무리·행동·성향·위험·인지·피격 대응·후보 점수를 기록한다. 약 5 MiB에서 이전 파일 하나로 순환한다.

브라우저 JSON에 `bandits`, `objective`, `counts.bandit_groups`를 추가했다. 기존 필드를 유지하고 화면에 야적 행동·성향·판단 점수와 현재 목표를 표시한다.

전체 8개 모델·42개 클립의 정점·UV·색상·프레임 변화·파일 길이를 오프라인으로 확인했다. `tests/RpgBanditTests.cpp`에는 밀도·무리 배치, 비선제공격·피격 대응·후퇴·정보 공유, 즉시 재생성 방지, 목표 진행·단일 보상 검사를 작성했다. 마을 경계 검사도 피격 대응 중인 야적 기준으로 갱신했다. C++ 테스트와 게임은 실행하지 않았다.

사용자 확인: 마을 출발 → 관찰하는 무리 지나치기 → 선제공격 후 동료 반응 → 부상·경비 근처 후퇴 → 레벨 3·E 회수 2개 → 경비 F 보고 → 재대화 보상 중복 없음. 다수 SD의 겹침·FPS·마을 진입 추적도 확인한다.
