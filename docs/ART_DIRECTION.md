# 아트 방향과 리소스 적용 기준

작성일: 2026-09-09 · 상태: 사용자 확정 방향 + 적용 설계안

## 1. 확정 방향

- 소녀전선 **1편의 리소스**를 사용한다. 캐릭터를 픽셀 아트로 새로 제작하거나 도트화하는 방향은 폐기한다.
- 실제 3D 지형과 고정 각도 쿼터뷰 카메라는 유지한다.
- 옥토패스 트래블러와 소드 오브 콘발라리아는 공간 구성과 2D/3D 결합의 참고다. 캐릭터의 화풍과 비례는 소녀전선 리소스를 기준으로 한다.
- 아래의 필드 배치, 배경 재질, UI 색상, 렌더링 정책은 우리 프로젝트에 맞춘 제안이며 원작 제작진의 공식 아트 규정이 아니다.

## 2. 조사에서 확인한 구성

소녀전선 1편은 일러스트레이터가 제작한 캐릭터 아트와 전투·숙소용 SD 캐릭터를 구분한다. 인물 소개와 감상에 쓰이는 상세 일러스트를 작은 필드 캐릭터와 같은 규격으로 취급하지 않는다. 일부 코스튬에는 Live2D 표현이 있으며 모든 캐릭터에 공통으로 존재한다고 가정하지 않는다.

아트 구성의 기준은 애니메이션풍 인물 표현과 총기·전술 장비의 조합이다. 다양한 캐릭터 의상과 작가별 표현 차이가 있으므로 전원을 단일 군복이나 동일한 채색 방식으로 다시 그리지 않는다. 원본의 얼굴, 의상, 무기, 실루엣을 보존한다.

조사 자료:

- [소녀전선 일본 공식 사이트 — SYSTEM](https://gf-jp.sunborngame.com/): 전투·편성·숙소 화면의 공식 참고.
- [공식 Google Play 소개 및 스크린샷](https://play.google.com/store/apps/details?id=com.sunborn.girlsfrontline.en): 캐릭터 일러스트와 전투 화면의 참고.
- [IOP Wiki M4A1](https://iopwiki.com/wiki/M4A1): 캐릭터별 일러스트·자료 확인용 팬 위키.
- [IOP Wiki Live2D 분류](https://www.iopwiki.com/wiki/Category:T-Dolls_with_Live2D): 일부 캐릭터/코스튬의 Live2D 여부 확인용 팬 자료.

공식 사이트의 개별 CDN 이미지 일부는 이번 조사 도구에서 로딩되지 않았다. 정확한 색상값·재질 규격을 공식 자료에서 추출한 것으로 취급하지 않는다.

## 3. 장면별 적용안

| 용도 | 사용할 표현 | 적용 방향 |
|---|---|---|
| 필드·전투 | 원작 비픽셀 SD 캐릭터 | 3D 공간에 카메라를 향하는 2D 캐릭터로 배치 |
| 대화·상세 화면 | 원작 인물 일러스트·표정 | 원본 비율 유지, UI 영역에 맞춰 크롭·배치 |
| 초상·편성 | 해당 인물의 일러스트·아이콘 | 같은 의상·버전으로 통일 |
| 특별 연출 | 확보된 CG 또는 지원되는 동적 리소스 | 일반 SD 애니메이션과 별도 경로로 관리 |
| 월드 배경 | 새 3D 지형·건물과 활용 가능한 원본 요소 | 군사시설·산업시설·거주지 등 세계관에 맞는 공간 |

원작 2D 배경 이미지는 그대로 충돌 가능한 3D 지형이 되지 않는다. 사용할 3D 지오메트리는 별도로 확보하거나 제작해야 한다. 인간 주인공의 필드 리소스도 아직 정하지 않았다.

## 4. 우리 게임의 배경·UI 제안

- 배경은 콘크리트, 금속, 도로, 수풀 등의 구분이 읽히는 절제된 재질을 사용한다. 캐릭터의 선과 색을 묻어버리는 고주파 디테일은 줄인다.
- 회색·카키·갈색 계열을 환경의 기본 후보로 두고, 안전한 거점에는 따뜻한 빛, 위험 구역에는 경고등 등의 포인트를 사용한다. 전체 지역을 같은 어두운 색으로 통일하지 않는다.
- UI는 작전 단말·보고서 느낌의 명확한 패널, 높은 글자 대비, 제한된 강조색을 기본 후보로 삼는다. 색상 팔레트와 폰트는 추후 정한다.
- 강한 심도 효과, 화면 전체의 도트화, 과도한 블룸은 기본 전제로 두지 않는다. 캐릭터와 이동 경로의 가독성을 먼저 확보한다.

## 5. 리소스와 렌더링 적용 기준

- 2026-09-14 원본 SD 5종을 추출해 30fps 정점 애니메이션으로 변환하고 C++에 연결했다. 게임 실행 검증은 미완료다. 상세 범위는 [CHARACTER_ASSET_INTEGRATION.md](CHARACTER_ASSET_INTEGRATION.md)를 따른다.
- 정적 이미지, 프레임 애니메이션, 파츠 기반 애니메이션을 구분한다. Spine 등의 형식과 런타임 버전은 실제 파일 확인 전 확정하지 않는다. Live2D와 전투용 SD 애니메이션도 별개로 취급한다.
- 원본 비율과 알파 경계를 보존하며 발밑 기준점과 화면상 캐릭터 크기를 통일한다. 큰 일러스트를 축소해 SD 대신 사용하는 것은 기본안이 아니다.
- 픽셀 정수배 확대나 nearest 필터를 일괄 강제하지 않는다. 원본 표시 품질에 맞춰 필터링·축소 품질을 검토한다.
- 투명도, 캐릭터끼리의 겹침, 건물에 가려짐, 발밑 접지와 그림자를 검토한다. 알파 처리 방식과 그림자 구현은 실제 리소스로 확인한다.
- 원본에 앞·뒤·대각선 방향이 없으면 먼저 사용 가능한 방향과 화면 구도를 정한다. 좌우 반전 시 무기·장비·문양의 비대칭도 확인한다.
- 인물 ID, 의상/개조 버전, 원작 시점, 사용 장면, 애니메이션 목록을 기록한다. 다른 시점의 외형이나 2편 리소스를 무심코 혼용하지 않는다.
- 첫 목표는 SD 캐릭터 하나를 작은 3D 바닥 위에 자연스럽게 표시하고, 가능한 대기·이동 동작과 충돌을 확인하는 것이다. 원본에 없는 동작은 미구현으로 기록한다.

## 6. 후속 결정 사항

사용할 첫 캐릭터, 리소스 위치와 형식, 인간 지휘관의 표현, 방향 수, 애니메이션 지원 범위, 3D 배경 제작 방식, 카메라 투영·배율을 후속 결정한다. 리소스 조사 결과를 기준으로 시제품 규격을 정한다.
