# 로컬 월드 모니터

작성: 2026-10-07

## 실행

1. Visual Studio에서 게임을 빌드하고 실행한다. 실행 파일 옆 Profiles/monitor.json이 0.5초마다 갱신된다.
2. 저장소 루트 PowerShell에서 다음을 실행한다.

~~~powershell
.\tools\monitor\start-monitor.ps1
~~~

브라우저에서 http://127.0.0.1:8765/가 열린다. 서버 창을 유지하고 종료할 때 Ctrl+C를 누른다. Python 3 표준 라이브러리만 사용하며 패키지 설치는 필요 없다. 실행기는 py, python, 이 PC의 Codex 번들 Python 순서로 찾는다.

PowerShell 정책으로 스크립트가 실행되지 않는 환경에서는 보안 설정을 바꾸지 말고 설치된 Python으로 직접 실행한다.

~~~powershell
py -3 tools/monitor/server.py --open
~~~

게임 출력 폴더가 다른 경우:

~~~powershell
py -3 tools/monitor/server.py --open --snapshot "C:\게임출력폴더\Profiles\monitor.json"
~~~

기본값은 저장소 BaseProject_SE 아래에서 가장 최근에 갱신된 상태 파일을 자동 선택한다. 여러 게임 인스턴스/Debug·Release를 동시에 사용하면 --snapshot으로 대상을 고정한다. 포트 충돌 시 --port 8766처럼 변경한다. HTML 파일을 직접 더블클릭하지 않고 서버 주소로 접속한다.

## 화면

- 전체 NPC 수, 체력 0 초과 NPC 수, 전투 불능·원격 임무 수.
- 살아 있는 몹 수와 전체 슬롯·재생성 대기 수를 분리.
- 마을별 등록/현장/외곽/원격 NPC, 부상·적대·전투 불능, 마을 내 몹, 건물, 기지 물자·구조 인원.
- NPC별 이름/직업/상태/행동·목표/체력/위치/탄약/기억·지식 수.
- 행 선택 시 작업·선택 이유·신뢰·존중·후보 점수를 포함한 NPC JSON 상세.
- 이름·직업·행동 검색, 마을/상태 필터, 마지막 수신 JSON 다운로드.
- 연결 실패/5초 이상 상태 미갱신/게임 일시정지/훈련/월드 데이터 오류 안내.

현재 구현된 마을은 변경 마을 한 곳이다. 기존 주민과 서사 동료를 모두 이 마을의 등록 인원으로 집계한다. NPC 외곽 이동/원정은 소속 변경이 아니다. 미래 다중 마을은 villages 배열 및 NPC의 village_id로 화면이 자동 구분하지만, 게임에 마을이 추가되면 송신 측 마을 소속/집계도 함께 연결해야 한다.

현재 정상 로드 시 주민 20명 + 서사 동료 2명이며 숫자를 HTML에 고정하지 않는다. 플레이어·F6 훈련 인형·실체 NPC로 등록되지 않은 구조 인원 숫자는 NPC 총수에서 제외한다. 몹 숫자는 현재 메모리의 적 풀을 의미하며 무한 지형 전체의 추정 개체 수가 아니다. 원격 동료의 좌표는 null로 전송한다.

마을 상태의 '경계 필요'는 적대 NPC 등록 또는 마을 내 살아 있는 몹이 있음, '치료 필요'는 부상/전투 불능 등록 NPC가 있음, 그 외는 '안정'이라는 표시 규칙이다. 별도의 치안 시뮬레이션 값이 아니다.

## JSON 수신 계약

게임 → 원자적 JSON 파일 교체 → 로컬 HTTP 서버 → HTML fetch.

- GET /api/snapshot, UTF-8 application/json. 브라우저는 1초 간격으로 요청한다.
- WebSocket 푸시가 아닌 HTTP 폴링 방식으로 JSON 메시지를 수신한다.
- schema_version: 1, type: snapshot, session_id: 프로세스 ID, sequence: 송신 순번, sent_at_ms: Unix 밀리초.
- game: 정지/훈련/전투 불능/시드/게임 시각/월드 준비·오류/무전 상태.
- counts: 전역 NPC·몹 집계. villages: 마을 집계 배열. npcs: 전체 NPC 배열.
- NPC ID는 town:0, world:1001처럼 기존 주민/서사 동료를 구분한다.
- world_event: 개발용 사건 상태/결과/예약 수. 사건 state는 0 Pending / 1 Active / 2 Resolved / 3 Expired.
- 서버가 추가하는 transport: 수신 시각, 메시지 나이, stale 여부, 읽은 파일 경로.
- 데이터 파일 미생성/손상/스키마 불일치는 HTTP 503 JSON error. 연결 복구 시 자동 재시도한다.
- 서버는 127.0.0.1에만 바인딩한다. 외부 CDN·인터넷 연결·게임 제어 API는 없다.

모니터는 개발용 실제 상태를 표시하므로 게임 속 NPC/플레이어의 지식 제한과는 별개다. 브라우저가 게임 객체를 직접 조회하지 않는다. 게임 메인 스레드에서 2Hz로 JSON을 만들고 임시 파일 완성 후 교체한다. 렌더 프레임마다 파일을 쓰지 않는다. 쓰기 실패 시 기존 정상 파일을 보존하고 콘솔에 실패를 알린다.

## 일시정지와 검증

브라우저로 포커스를 옮기면 현재 게임의 자동 일시정지 규칙이 적용된다. 이 규칙은 변경하지 않았다. 일시정지 중에도 JSON 송신은 지속되므로 '연결됨 · 게임 정지'가 표시된다. 다른 모니터에 브라우저를 띄우고 게임에 포커스를 둔 상태로 관찰할 수 있다.

게임 종료 시 파일은 마지막 상태로 남고 5초 후 수신 중단으로 표시된다. 새 게임이 실행되면 자동 갱신된다. 게임 최소화 등으로 타이머 자체가 멈춘 경우에도 같은 상태를 표시한다.

이번 검증: Python 모니터 테스트 4개(UTF-8/다중 마을, 오래된 상태, 손상/누락, 실제 로컬 HTTP JSON·오류·허용 경로), JavaScript 문법, 프로젝트 파일 등록과 코드 포맷 확인. C++ 빌드·게임 실행·실제 브라우저 화면 검증은 사용자 확인 전이다.

~~~powershell
py -3 -m unittest discover -s tools/monitor -p test_server.py -v
~~~

## 2026-10-12: 별도 브라우저 창과 마을 사회 상태

파일 탐색기에서 tools/monitor/OpenMonitor.cmd를 더블클릭해 모니터 서버와 브라우저를 연다. 기존 PowerShell 실행기도 계속 사용할 수 있다. 브라우저 정책에 따라 새 탭으로 열리면 화면 우측의 **별도 창으로 열기**를 눌러 독립 창으로 분리한다. 서버 콘솔은 켜 둔다. 게임에 새 송신 코드가 포함되도록 빌드 후 실행해야 한다.

추가 JSON 필드 (schema_version 1의 선택 필드 확장):

- villages[].population: 생존한 등록 NPC 수. 실제 마을 내 인원은 npcs_present, 원격 인원은 npcs_remote로 별도 표시.
- villages[].atmosphere: label, reason, basis. 교전/적대/부상과 기지 인원이 인지한 소식으로 계산한 모니터링 요약이며 감정 시뮬레이션 데이터가 아니다.
- villages[].tendencies: rescue_priority, command_obedience, autonomy, basis. 생존 등록 NPC들의 현재 행동 성향 평균(0~1).
- villages[].rumors[]: id, text, holders, confidence, observed_minute, sources, basis. 기지 안에 실제 배치되어 있는 서사 동료의 Belief에서 집계한다. sources는 해당 내용을 알고 있는 인물 이름이고 confidence는 그들의 평균 확신도다.
- 원정 중인 인물만 아는 결과는 마을 소문으로 추가하지 않는다. 미확인/성공/부분 성공/실패 믿음이 공존하면 별도 소식으로 표시한다. 모니터가 소문을 만들거나 NPC에게 새 정보를 전파하지 않는다.

분위기 표시 우선순위: 생존 인원 없음 → 긴장(교전/적대/진입 몹) → 걱정(부상/전투 불능) → 침울(실패 소식) → 안도와 걱정(부분 구조) → 안도(성공) → 불안(미확인 실종 소식) → 평온.

신규 필드가 없는 이전 게임 JSON도 읽을 수 있으며 관련 항목은 미수신/정보 없음으로 표시한다. 게임에 현재 있는 마을은 한 곳이며, 다른 마을은 실제 마을 등록/송신 로직을 추가한 후 표시된다.

검증: Python 서버 검사 5개와 Node 기반 화면 동작 검사(마을 사회 상태·이전 형식 호환·원격 필터·상세·별도 창·수신 중단) 통과. C++는 포맷·정적 검토만 했으며 게임 빌드/실행 및 실제 브라우저 레이아웃 확인은 사용자 담당이다.
