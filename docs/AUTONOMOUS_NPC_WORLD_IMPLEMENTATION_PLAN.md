# 자율 NPC 서사·월드 시뮬레이션 구현 계획

작성: 2026-10-01
상태: **설계 제안. 이번 작업에서 소스·프로젝트 파일은 수정하지 않으며 빌드·실행하지 않는다.**

## 1. 범위와 판단

사용자가 첨부한 `Autonomous NPC Narrative & World Simulation System` 0~70절을 기준으로 한다. 첨부의 구현 지시보다 이번 사용자의 **구조 분석과 계획만 작성** 요청을 우선한다.

기존 NPC AI를 버리지 않고 그 위에 장기 목표·월드 사건·대화를 추가한다. 첫 구현은 작은 기지, 플레이어, 미라·벨, 실종 인형 사건 하나가 처음부터 끝까지 연결되는 범위다. 기존 마을 20명과 일반 RPG 사냥은 유지하고, 미라·벨은 별도의 시험 동료로 추가하는 안을 제안한다. 두 이름은 명세의 시험 인물이며 원작 등장인물이라고 확정하지 않는다.

전체 Manager 목록을 빈 클래스로 먼저 만드는 방식은 피한다. 첫 사건에 필요한 데이터와 실행 경계를 먼저 만들고 후속 기능은 그 경계를 통해 확장한다. 새 시스템은 C++17의 값 타입과 조합을 우선하며 새 ECS나 스크립트 런타임 도입을 전제하지 않는다.

현재 작업 트리에는 앞선 NPC 작업의 미커밋 변경과 신규 파일이 있다. 이를 분석 기준으로 삼으며 되돌리거나 별도 완료 상태로 간주하지 않는다.

현재 소스에는 공통 `Actor`/`SceneGraph` 클래스가 확인되지 않는다. `Renderer::Actors()`는 그리기 함수이며 Actor 클래스가 아니다. GOAP, 감정·Mood, 유전 진화, 부대 문화, 월드 사건, 세력 AI, 영속 저장도 현재 구현된 기능으로 가정하지 않는다.

### 먼저 해결해야 할 결합

1. **시간:** `RpgGame::time`은 전투·애니메이션용 float 초다. Update는 dt를 0.1초로 제한하고 작은 Step으로 나눈다. 이를 며칠짜리 달력으로 직접 재사용하거나 가속하면 전투·정보 만료까지 달라진다.
2. **ID:** `npc.id`를 `npcs[id]`로 접근한다. 삭제·사망·원정·동적 추가 이후에도 유지되는 정체성과 배열 위치가 분리되어야 한다. 적 슬롯 재생성도 이전 적의 기억과 구분해야 한다.
3. **지식 수명:** 모든 현재 믿음은 최대 5초다. 전투 위치 정보에는 적절할 수 있으나 실종·출발·구조 보고에는 사용할 수 없다.
4. **중복 상태:** `TownNpc::trust/respect`와 `mind.relationships[-1]`, 문자열 이력과 구조화 기억이 병존한다. 관계의 단일 소유자를 정하고 이력은 표현용으로 제한한다.
5. **생명 상태:** 주민 체력 0은 30초 뒤 자동 회복한다. 원정 실종·부상·사망을 같은 hp 규칙으로 처리하면 서사 결과가 사라진다.
6. **직접 변경:** 거래·지원·처치가 자원과 관계를 곧바로 수정한다. 장기 사건 결과는 공통 해결 경로로 통과시켜 중복 적용을 막아야 한다.
7. **화면 밖 동작:** 모든 주민이 UpdateTown을 돈다. 플레이어와 멀어진 적은 플레이어 주변으로 재배치된다. 이 적 풀은 원격 원정의 적 전력이나 영속 사건 참여자로 사용할 수 없다.
8. **대화:** 현재 직업별 1·2 분기는 조건부 대화 트리가 아니다. 장기 목표의 우선순위에 따른 거절/중단과 선택 직전 재검사가 필요하다.

## 3. 소유 구조와 추가 클래스

`RpgGame → WorldSimulation → 월드 데이터 + 기능 시스템` 구조를 제안한다. 시스템은 같은 데이터를 각각 복제하지 않는다. 첫 단계에는 아래 책임들을 소수 파일에 묶어도 되며, 클래스마다 무조건 한 쌍의 파일을 만들 필요는 없다.

### 기반과 월드

| 제안 타입 / 파일 | 책임과 소유권 | 도입 시점 |
|---|---|---|
| `ActorId`, `EventId`, `RegionId`, `LocationId` / `WorldTypes.h` | 저장 가능한 강한 ID. 무효 ID와 플레이어를 -1 하나로 혼용하지 않음 | 1차 |
| `GameClock` / `GameClock.h/.cpp` | 정수 기반 월드 시각, 일·시·분 표시, 시간 배율, 마감 시각 | 1차 |
| `WorldActorRegistry` / `WorldActor.h/.cpp` | 플레이어·NPC의 안정 ID 조회. 소속·위치·생명 상태 및 NPC 컴포넌트의 영속 소유 | 1차 |
| `WorldState` / `WorldState.h/.cpp` | Canon 읽기 전용 정의, 지역 자원/구조 인원, 개인 상태 접근 경계 | 1차 최소형 |
| `WorldSimulation` / `WorldSimulation.h/.cpp` | 갱신 순서·예산·대기 중 요청·알림 처리. RpgGame이 한 개 소유 | 1차 |
| `SimulationEventBus` / `SimulationEvent.h/.cpp` | 부상·귀환·관계 변화 같은 타입 있는 알림을 큐로 전달 | 1차 |
| `WorldEventSystem` / `WorldEvent.h/.cpp` | 진행 중 사건, 참여자·의도·소유권·기한·진행 단계 보관 | 1차 |
| `EventResolver` / `EventResolver.h/.cpp` | 유효성 검사, 자원 예약/소비, 결과 확정과 효과의 1회 적용 | 1차 |
| `WorldLog` / `WorldLog.h/.cpp` | 개발용 사건 추적과 플레이어가 알게 된 사건 기록의 서로 다른 조회 | 1차 |

명세의 `WorldActor`는 **세계에 의사결정 주체로 존재하는 데이터**로 해석한다. 화면에 없는 동안에도 존재한다. 초기에는 Player/NPC 유형과 정책을 조합하고 Faction 유형은 예약한다. 실제 세력 AI는 후속이다.

이전 Actor/SceneGraph 방향과 연결할 때에는 영속 WorldActor를 화면의 Actor가 ID로 참조하도록 한다. SceneGraph는 배치·가시성·공간 검색을 담당하고, 화면에서 잘렸다는 이유로 NPC의 사건 진행이나 존재 자체를 중단하지 않는다. 공통 렌더 Actor 전면 개편은 이번 프로토타입의 선행 조건으로 잡지 않는다.

### NPC 컴포넌트와 실행

| 제안 타입 / 파일 | 역할 | 기존 코드 연결 |
|---|---|---|
| `NpcIdentity`, `NpcSkills`, `NpcLifeState` / `NpcProfile.h` | 가치·두려움·욕망·갈등, 전투/전술/의료 등 능력, Alive/Injured/Missing/Dead | TownNpc의 이름·성향·체력과 매핑. 피해와 사망을 분리 |
| `NpcMind` 확장 | 지식·기억·Needs·방향성 관계의 소유자 | 현재 자료구조를 이관·확장. 정적 성격과 가변 행동 성향 구분 유지 |
| `NpcGoalComponent`, `NpcGoalEvaluator` / `NpcGoals.h/.cpp` | 개인 목표 후보·우선순위 기여·현재 목표·전환 억제 | 현재 즉시 행동 Utility보다 상위 계층. 이름별 하드코딩 금지 |
| `NpcTaskRunner` / `NpcTasks.h/.cpp` | 준비→기지 출구 이동→원정→귀환→보고 실행 | MoveNpc/치료/휴식 등을 어댑터로 호출. 첫 버전은 GOAP 아님 |
| `NpcSimulationSystem` / `NpcSimulation.h/.cpp` | 근거리·기지·원격 갱신 선택, 상위 목표와 하위 행동의 조정 | UpdateTown을 단계적으로 위임. 원정 NPC가 동시에 순찰하지 않게 함 |
| `RelationshipSystem` / `NpcRelationships.h/.cpp` | 구조·협력·거절 결과로 관계를 갱신하는 규칙 | 값은 NpcMind 한 곳에만 저장. trust/respect/debt 재사용, 나머지 관계축 확장 |
| `NpcSchedule`, `PersonalStory`, `StoryletSystem` | 일과·개인 갈등의 상태 전이·조건부 소규모 사건 | 프로토타입 통과 후. 초기 귀환/부상 상태를 전체 PersonalStory로 부르지 않음 |

영속 위치는 `locationId + regionId + 이동 상태/경로 + 도착 예정 시각`으로 표현한다. 근거리 실행에는 월드 좌표·BFS 경로·애니메이션이 추가된다. 로컬 객체가 제거되어도 ID와 개인 상태는 남는다. 현재 `DollPoint` 등 공통 위치 타입이 훈련 헤더에 의존하는 부분도 이관 시 정리한다.

첫 대화는 F 접근, 방향키 또는 번호로 선택, 확인·종료로 구성한다. 키 중복은 구현 시 기존 조작표와 대조한다. 거래 메뉴는 기존 동작을 어댑터로 유지한다. 대화는 전체 세계를 정지시키지 않으며 위험·출발 목표가 더 중요해지면 이유를 말하고 종료한다. 명시적인 일시정지는 모든 시뮬레이션을 멈춘다.

## 4. 가장 중요한 실행 계약

### 진실·정보·원작의 경계

- Canon: 읽기 전용 사건 정의. 지역/개인 효과 요청으로 변경할 수 없도록 Resolver에서 검증한다.
- Regional: 자원·구조 인원·가용 인력·보급 등 변동 가능 상태. 처음에는 사건에 필요한 항목만 둔다.
- Personal: 생명 상태·소속·기억·관계·현재 목표. 개인 상태가 허용되지 않은 원작 결과를 뒤집지 않게 한다.
- NPC GoalEvaluator와 대사는 `ActorKnowledgeView`만 입력받는다. 원격 진실 전체를 받지 않는다. Resolver는 결과 판정을 위해 진실을 읽을 수 있다.
- 단기 위치 정보와 장기 사건 지식을 구분한다. 사건 지식은 sourceEvent, 정보 출처, 관측 시각, 신뢰도, 명제 상태를 가진다. 모름/생존 추정/사망 확인은 서로 다르다.
- 기존 세계관 문서의 시작 연도·사건 시점은 미정이다. 첨부의 원작 사건명은 계층의 예시로만 취급하며 테스트 이틀 경과가 후반 원작 사건을 자동 발생시키지 않는다.

### 시간과 사건 처리 순서

전투·이동은 기존 고정 소규모 Step을 유지하고, GameClock은 별도 달력 시각을 만든다. 월드 배율이 스프라이트나 사격 속도를 바꾸면 안 된다. 제안 기본 배율은 실제 1초=게임 1분으로 두되 설정 가능하게 하고, 검증용 다음 사건/마감까지 진행 기능을 제공한다. 실제 이틀 동안 기다리게 만들지 않는다.

일시정지·F6 훈련·게임 종료 중 월드는 정지하는 것을 첫 버전 기본값으로 제안한다. 프로그램 종료 중 실시간 진행은 범위 밖이다. 저FPS나 시간 건너뛰기에서도 마감 사건을 빠뜨리지 않도록 월드 스케줄러는 이전 시각~현재 시각 사이의 예약 사건을 시각/ID 순으로 처리한다. 처리 예산을 넘으면 미처리 시간을 보존하며 마지막 시각으로 단순 점프하지 않는다.

한 시뮬레이션 단계는 다음 순서를 가진다.

1. 시간 진행과 예약 사건 활성화.
2. 관측·통신·보고로 각 Actor 지식 갱신.
3. 해당 NPC의 목표 후보 계산, 선택 및 의도 제출.
4. 자원·참여 가능 여부와 DecisionOwner 검사, 충돌 조정.
5. 로컬 Task 또는 원격 진행 처리.
6. 결과 검증·상태 효과 확정 후 타입 있는 알림 발행.
7. 기억·관계·대화 상태·로그 갱신. 파생 사건은 다음 처리 단계로 큐잉.

WorldEvent는 지속되는 문제이고 EventBus 메시지는 이미 일어난 변화의 알림이다. 둘을 같은 타입으로 섞지 않는다. 매 프레임의 판단을 모두 영속 WorldEvent로 만들지 않고, 목표 확정·참여/거절·자원 투입 같은 의미 있는 선택을 해당 사건의 DecisionRecord로 기록한다.

### 중복 해결과 결과 소유권

- 사건은 Proposed/Active/Resolving/Resolved/Expired 등의 수명을 갖고, 원정은 Preparing/Departing/Travelling/Searching/Returning/Completed로 별도 관리한다. 사건 해결과 귀환 시점은 다르다.
- `(EventId, ResolutionVersion, EffectId)`로 결과 적용을 식별한다. 저장/로딩·재시도·중복 알림이 구조 인원이나 자원을 다시 증가시키지 않는다.
- 플레이어와 NPC의 행동은 같은 사건의 참여 요청으로 들어간다. 도착·수행·기한 경합은 시각과 안정 ID로 순서를 고정한다. 같은 대상 구조를 두 번 보상하지 않는다.
- NPC의 선택은 목표 점수로 설명한다. 결과의 제한적 난수는 월드 seed/사건 ID 기반 전용 스트림을 쓰고 판정 입력·추출값을 기록한다. 렌더 FPS가 결과를 바꾸지 않게 한다.
- 근거리 실제 플레이와 원격 결과 계산은 한 원정에 대해 동시에 작동하지 않는다. 첫 버전은 출구~귀환까지 원격 처리 구간을 고정하고 도중 현장 진입은 제공하지 않는다. 이후 전환 시 진행률·소비 자원·부상과 결과 권한을 인계한다.

## 5. 첫 프로토타입의 플레이 흐름

1. 기존 마을의 작은 기지 구역과 출구를 재사용한다. 미라·벨 및 실종 대상 ID를 등록한다. 실종 대상은 화면 밖의 영속 인물 데이터이며 필요할 때만 배치한다.
2. 생성 시각과 2게임일 기한을 가진 MissingDoll 사건을 생성한다. 구조 신호를 실제 수신한 Actor에게만 알려진 사건으로 전달한다.
3. 플레이어는 접근 대화로 참여·물자 지원·자율 판단 허용·거절을 선택할 수 있다. QuestView는 이를 사건 참여 상태로 표시한다.
4. 아무 선택도 하지 않아도 일정 시각에 미라가 구조/대기/지원 요청/포기 후보를 평가한다. 벨은 구조 동행/기지 방어/대기 후보를 관계·성격·능력·알고 있는 위험으로 평가한다.
5. 참여자가 준비 물자를 예약하고 출구까지 실제 이동한다. 출구 도달 확인 뒤 원격 원정으로 전환한다. 경로 막힘은 재탐색→제한 시간 후 계획 실패/다른 선택으로 처리한다.
6. 원격 결과는 스킬·자원·위험·시각에 따라 성공/부분 성공/부상/구조 실패로 나뉜다. 아무도 출발하지 않으면 마감 결과가 반드시 발생한다.
7. 결과가 지역 자원·구조 인원·동료 상태를 바꾸고, 귀환 시 출구에서 다시 등장한다. 부상자는 치료 위치로 이동한다. 영구 사망자는 기존 30초 회복 로직의 대상이 아니다.
8. 당사자는 경험을 기억한다. 귀환 보고를 받기 전의 플레이어는 원격 결과 전체를 알 수 없다. 보고 뒤 대화와 세계 기록이 달라진다.

시험용 기본 수치는 미라가 구조를 선호하도록 설정하지만 이름을 검사해 구조를 강제하지 않는다. 같은 데이터의 다른 NPC도 같은 판단 규칙을 사용하며, 관계·자원·위험을 바꾸면 벨의 동행 여부 등이 달라져야 한다.

플레이어 참여 경로도 첫 완성 범위에 포함한다. 플레이어 동행을 선택한 경우 기지 인근의 작은 수색 지점에서 접근·구조 상호작용을 수행하고, 동일한 사건 해결 요청으로 보고한다. 원격 원정 중간에 순간 합류하는 기능은 후속이며, 참여 가능 시점은 선택지에 표시한다.

## 6. 구현 단계와 완료 조건

| 단계 | 작업 | 완료 판단 |
|---|---|---|
| 0 | 현재 동작 기준과 테스트 고정, ID/상태 이관 위치 확정 | 기존 거래·사냥·F6·20명 데이터 보존 목록 작성 |
| 1 | GameClock, 안정 ID/등록소, NPC 프로필·생명 상태·관계 단일화 | 일시정지/시간 도약, ID 유지, 실종/사망이 자동 회복되지 않음 |
| 2 | WorldState 최소형, WorldEvent·Resolver·알림 큐, 사건 추적 로그 | 기한 처리, 효과 1회 적용, Canon 변경 거부 |
| 3 | 사건 인식·장기 지식, 개인 목표 평가, 동행 판단, Task 실행 | 플레이어 입력 없이 인식→결정→출발, 판단 근거 추적 가능 |
| 4 | 원격 원정 해결·귀환, 기억/관계/지역 효과 | 성공/부분 성공/실패·단독/동행 경로 모두 종료 가능 |
| 5 | 조건부 대화·NPC 거절/중단·QuestView·플레이어 참여 | 대화가 실제 기억/정보를 반영하고 플레이어도 같은 사건에 개입 |
| 6 | NPC/사건 디버그 UI 완성, 성능·회귀 검증 | 아래 인수 기준을 재현 가능하게 확인 |

첨부의 전체 17단계는 장기 로드맵으로 유지한다. 단, 첫 프로토타입의 성공 조건에 필요한 지역 상태 최소형과 디버그 기록은 초반부터 만든다. 전체 지역 시뮬레이션과 완전한 디버그 UI를 초반에 구현한다는 뜻은 아니다.

프로토타입 통과 후 확장 순서는 명세대로 GOAP → Storylet → 사회적 모방 확장 → 유전 진화 → 지역 시뮬레이션 → 세력 AI를 따른다. Schedule/PersonalStory/Emotion·Mood는 해당 단계의 입력 모델로 점진 도입한다. 저장/불러오기는 장기 다일 플레이로 확대하기 전에 별도 필수 단계로 둔다.

## 7. 저장·확장·성능 설계

첫 구현의 메모리 상태는 재시작 시 초기화되는 시험판으로 명시한다. 초기부터 저장 가능한 DTO를 쓰고 포인터·문자열 주소·벡터 인덱스를 영속 식별자로 저장하지 않는다.

저장 단계에서는 버전, ID 발급 상태, 게임 시각, RNG 상태, 인물 프로필/목표/작업/위치/관계/기억/신념, 사건/원정/예약 자원, 적용 완료 효과, 지역 상태, 중요한 사건 이력을 함께 저장한다. 런타임 경로·렌더 캐시는 로드 후 재구성한다. 중요 서사 사실은 24개 기억에서 퇴출되어도 사라지지 않도록 별도 요약·영속 사실로 보존한다.

시뮬레이션 수준은 제안치로 시작해 측정으로 조정한다.

- L0 근거리: 이동·전투는 기존 Step, 인지 5Hz·전술 판단 2Hz 재사용.
- L1 같은 기지/지역: 장기 목표를 낮은 빈도로 평가. 예약된 활동 변화 및 긴급 사건 때 즉시 갱신. 사용하지 않는 경로 탐색은 생략.
- L2 원격: 출발/도착/탐색/기한 등 예약 사건만 처리. 프레임마다 이동·교전 계산 금지.
- 단계 전환에 거리 여유와 최소 유지 시간을 둬 왕복 전환을 억제한다. 두 NPC부터 적용하고 기존 20명 전체 전환은 회귀 확인 뒤 확대한다.
- 모든 인물 쌍·사건 전체를 매 프레임 순회하지 않는다. 지역/참여자/관심 종류별 목록과 다음 시각 우선순위 큐를 사용한다.

AI 친화 로그: `simulation_tick`, `game_time`, `actor_id`, `event_id`, `decision_id`, `known_facts`, `candidate_scores`, `score_contributions`, `selected_goal`, `reason_code`, `task_state`, `resolution_version`, `effects_applied`, `simulation_level`.

성능 로그: `cpu_world_update_ms`, `cpu_goal_eval_ms`, `cpu_resolver_ms`, `cpu_dialogue_ms`, `cpu_log_write_ms`, `queue_depth`, `events_processed`, `deferred_events`, `active_actor_count`, `plan_failures`. 누적 구간의 포함 관계와 집계 단위를 문서화하고 p95/최댓값을 확인한다. 원인 로그는 상태 전환 때 기록하며 동일 후보 전체 덤프는 선택 NPC 또는 진단 모드에 제한한다. 회전 JSONL은 진단용이고 영속 세계 이력 저장소를 대체하지 않는다.

## 8. 인수·회귀 확인 계획

구현 단계에서 코어 자동 검사 소스를 추가하고, 사용자 요청 원칙에 따라 C++ 빌드·게임 실행은 사용자가 수행한다.

- 방치: 플레이어 무입력에도 사건 인식→독자 출발→해결→귀환→대화 변화.
- 선택 차이: 동일 상황에서 관계·위험·스킬을 바꾸면 후보 점수와 동행 판단이 바뀜. 거절 이유 표시.
- 무지: 미수신 NPC가 실종 사건에 반응하지 않으며 보고 전 플레이어에게 결과 누출 없음.
- 기한: 아무도 출발하지 않음, 마감 직전 구조, 시간 도약, 도착과 마감 동시 발생 모두 단일 결과.
- 참여: 플레이어 해결과 NPC 해결 요청 경합 시 구조/자원/보상 중복 없음.
- 귀환: 원정 중 거래·대화 불가, 귀환 위치 정상, 부상/실종/사망 상태 일관성.
- 기억: 당사자와 목격/전달받은 사람의 기억이 다르며 방향성 관계가 자동 대칭화되지 않음.
- 대화: 선택 표시 후 상황이 바뀌어도 재검사하며 긴급 목표가 대화를 중단할 수 있음.
- 재현: 같은 초기 상태·seed·입력 순서에서 결과 재현. 렌더 프레임률과 무관.
- 회귀: WASD·공격·경험치·거래·기존 NPC 20명·F6 훈련 유지.
- 성능: 근거리/원격 각각 실행 비용과 큐 적체 기록. 화면 밖 원정에서 BFS/전투 갱신이 수행되지 않음.
- 원작 보호: 지역 결과가 Canon 수정 요청을 발생시키더라도 거부되고 원인 기록.

미정 사항은 본편 연도/작전 지역, 미라·벨 최종 캐릭터 설정, 영구 사망의 본편 정책, 최종 시간 배율이다. 이는 프로토타입용 데이터·정책으로 격리하며 이번 계획에서 원작 설정이나 최종 밸런스로 확정하지 않는다.
